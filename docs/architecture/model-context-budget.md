# 模型上下文与富数据隔离

AetherX 的界面数据、持久化数据和模型上下文属于三个不同边界。桌面 Hub 与 Android Local Hub 必须遵循同一套约束，避免图片、附件或完整业务记录被误送进模型请求。

## 数据分层

1. **持久化层**保存完整记录。日记正文、头像、图片引用和同步元数据都不能因为模型预算而丢失。
2. **界面层**读取完整业务数据。相册、日记和工具活动卡片仍可展示原图及完整内容。
3. **模型投影层**只提供完成推理所需的有界信息。工具结果进入模型历史前必须经过 `ToolRegistry.modelResult()`。
4. **请求预算层**在调用模型提供方前再次校验整个消息窗口，处理历史版本遗留的超大工具结果。

模型预算不得反向修改持久化记录，也不能以删除历史会话作为常规修复手段。

## 工具结果契约

工具可以向界面返回完整的 `content`、`data` 和媒体数据，但模型只接收投影结果：

- Data URL、长 Base64 和二进制字段替换为媒体占位符；
- 单个未知工具结果最多约 32,000 字符；
- 字符串、数组、对象深度和字段数量均有上限；
- 富数据工具应实现 `projectResult`，保留对推理真正有用的字段；
- 日记工具仅向模型提供 ID、类型、标题、心情、周期、时间、消息数量和短节选，完整正文仍只留在业务数据中。

新增插件工具时，如果结果可能包含图片、长正文、文件、归档或批量记录，必须提供语义明确的 `projectResult`，不能只依赖通用截断。

## 会话窗口

会话历史按完整语义组裁剪：普通消息为一组，带 `tool_calls` 的 assistant 消息与其全部 tool 响应为一个不可拆分组。裁剪时同时遵守消息数量和字符预算，保证：

- 最新用户消息始终优先；
- 不产生孤立的 tool 响应；
- 不产生缺少 tool 响应的 assistant 调用；
- 历史中的 Data URL 在发送前被移除；
- 系统上下文和普通历史分别使用预算，避免一方完全挤占另一方。

当前请求边界约为：系统上下文 40,000 字符、历史上下文 120,000 字符。它们是提供方调用前的安全上限，不代表数据库保存上限。

## 双 Hub 一致性

- 电脑 Hub 在 Agent 工具执行完成后调用共享 Tool Registry 的模型投影，并由 AI Provider Client 做最终预算检查。
- 手机 Hub 使用同一份 Tool Registry 投影工具结果，并在直连模型提供方前执行等价的历史分组与总预算检查。
- 同步的是完整业务记录和已经保存的模型历史；每个活动 Hub 都必须在发送请求时重新执行投影和预算检查，以兼容旧数据。

## 回归要求

至少覆盖以下场景：

- 多篇带 Base64 配图的日记仍可在界面完整展示；
- `journal.list` 的模型结果不包含 Data URL；
- 未声明专用投影的富数据工具也不会突破通用上限；
- 旧会话中的超大工具结果会在请求边界被压缩；
- 工具调用链在裁剪后保持完整；
- 电脑 Hub 与 Android Local Hub 使用相同的行为约束。
